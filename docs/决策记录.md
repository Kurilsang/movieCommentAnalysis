## 九、研究结论（已核实事实，2026-10-12）

> 来源：子代理通过 Maven Central `maven-metadata.xml`、GitHub API、PyPI JSON API、hf-mirror.com、各厂商官方文档核实。
> ⚠️ 子代理环境限制：`web_search` 全程不可用（HTTP 402）；`huggingface.co` 网络不可达（`hf-mirror.com` 可用）；`raw.githubusercontent.com` TLS 失败。部分厂商价格（智谱、Kimi）页面为 JS 渲染，**未能核实**。

### 9.1 技术栈版本（已核实）

| 组件 | 坐标 | 版本 | 日期 | 许可证 |
|---|---|---|---|---|
| ONNX Runtime Java | `com.microsoft.onnxruntime:onnxruntime` | **1.31.0** | 2026-10-09 | MIT |
| DJL Tokenizers | `ai.djl.huggingface:tokenizers` | **0.38.0** | 2026-09-09 | Apache-2.0 |
| HanLP 1.x | `com.hankcs:hanlp` | **`portable-1.8.6`** ⚠️ | 2024-12-28 | Apache-2.0 |
| DashScope Java SDK | `com.alibaba:dashscope-sdk-java` | **2.23.2** | 2026-10-08 | — |

**⚠️ 坐标陷阱（写错必编译失败）**
- HanLP 1.x 在 Maven Central **只发布 `portable-*` 版本**，必须写 `<version>portable-1.8.6</version>`，写 `1.8.6` 会失败。
- Lucene 在 **9.0.0** 把 `analyzers-*` 改名为 `analysis-*`。`lucene-analyzers-smartcn` 止于 8.11.4，须用 `lucene-analysis-smartcn`（10.5.2, 2026-10-03）。

**⚠️ Windows 环境风险（最高优先级）**
- DJL 官方文档原文警告：ONNX Runtime 1.21.0+ 在 Windows 上用 VC 14.42 编译，**与部分 JDK 发行版冲突，会抛 `UnsatisfiedLinkError`**。官方测试过 **temurin17 与 zulu17** → **必须锁定 Temurin 17 或 Zulu 17**。
- ONNX Runtime 还需要 **MSVC++ Redistributable**（维护者承认此依赖未文档化，见 issue #24310）。
- **不要用 `onnxruntime-extensions`**：停留在 0.13.0（2024-10-31），仅发布过 3 个版本。

**已死/不可用（避免踩坑）**：DL4J（2022-08 后无发布）；Ansj（2018）；jieba-analysis（2015，且 POS 功能已移除）；Tribuo（**完全不支持 transformer**）；`langchain4j-onnx-scoring`（是 RAG reranker，返回单个 `Double`，**不是分类器**）；Spring AI 的 `TransformersEmbeddingModel`（只有 embedding，**无分类头**）。
**LangChain4j 中文 provider 模块**（dashscope / zhipu-ai / qianfan）**冻结在 0.36.2（2024-11-21）**，只有 community 模块是新的。

### 9.2 中文预处理选型（已核实）

**唯一满足"纯 Java、含分词+词性+NER、无 Python"的方案：HanLP 1.x `portable-1.8.6`**（Apache-2.0，7.6 MB，零传递依赖）。
限制：① **功能冻结**（提交信息为"常规维护"，约 1 年 1 版）；② **portable jar 不含依存句法分析数据**；③ **无情感模型**（`classification/` 只是通用可训练分类器）；④ NER 是词典驱动（nr/ns/nt），非神经网络，对影评黑话较弱。
**许可证不对称**：HanLP 1.x = Apache-2.0（可商用）；HanLP 2.x 模型与免费 REST API = **CC BY-NC-SA 4.0（仅非商用）**。

### 9.3 模型选型（已核实）——⚠️ 影响"不训练"决策

**核心结论：质量可用的中文情感模型几乎都不提供 ONNX，且多数没有许可证。**

| 模型 | 下载 | 许可证 | 大小 | ONNX |
|---|---|---|---|---|
| **`IDEA-CCNL/Erlangshen-Roberta-110M-Sentiment`** | 4,769 | **apache-2.0** ✅ | 390 MB | ❌ **需自行导出** |
| `uer/roberta-base-finetuned-jd-binary-chinese` | 5,234 | **无** | 390 MB | ❌ |
| `uer/roberta-base-finetuned-dianping-chinese` | 3,406 | **无** | 390 MB | ❌ |
| `William-g7/chinese-sentiment-onnx` | **27** | **无** | 516 MB | ✅（"量化版"同为 516 MB，**基本确定未量化**） |
| `foxyanuo/chinese-chat-sentiment-8class` | 128 | cc-by-nc-4.0 | 624 MB | ✅（8 分类，非二分类） |
| `hfl/rbt3`（3 层蒸馏） | 7,215 | apache-2.0 | **149 MB** | ❌（且是 backbone，未针对情感微调） |

**⇒ 唯一可用的合规方案：自行导出 `IDEA-CCNL/Erlangshen-Roberta-110M-Sentiment` 到 ONNX。** `optimum-cli export onnx` 一条命令，再 `quantize_dynamic` 转 int8（约 100 MB）。**推理期不需要 Python。**
⚠️ **HF 上不存在中文 TextCNN / FastText / TinyBERT 情感模型**（三种都搜过，零相关结果）。
⚠️ **`shibing624/text2vec-base-chinese` 是 embedding 模型，不是情感分类器**（966k 下载，极易误用）。

### 9.6 爬取合规（2026-10-12 实测）

| 站点 | robots.txt | 实测状态 |
|---|---|---|
| **豆瓣** | **明确 Disallow `/j/`** | `movie.douban.com/j/subject/{id}/comments` → **HTTP 200，无需登录，`retcode:1`** —— 但**每次仅返回 4 条评论**，且 `total_num` 明文暴露 |
| 猫眼 | `Allow: /` 后紧跟 `Disallow: /`，**自相矛盾 = 实质全禁** | HTTP 200 |
| MTime | `Disallow: /?*`，Allow `/news/` `/api/` | **存活**（HTTP 200，65 KB），**并未关站** |
| B 站 | 禁止 `/medialist/detail/`、`/index.html` | `api.bilibili.com/x/v2/reply` → **HTTP 200，`code:0`** |
| 微博 | **`ai-train=no`**，并**点名屏蔽 DeepSeek、Kimi、豆包、ChatGLM 等** | — |

**三条改变计划的发现**：
1. **豆瓣 `/j/` 正是 robots.txt 明确禁止的路径** —— 抓取它属于**有据可查的 ToS 违反，不是灰色地带**。论文若写"合规性"一节，这是硬伤。
2. 每次仅 4 条 ⇒ 单部电影 66.8 万条评论需 **约 16.7 万次请求**，绝非毕设量级。
3. 微博 robots.txt 已显式声明 `ai-train=no` 并点名屏蔽多家 AI 厂商 —— 用微博数据训练模型已被明确反对。

**法律框架（供论文引用）**：PIPL 适用于个人信息（含用户名的公开评论即属之）；《数据安全法》《网络安全法》适用于数据处理；《反不正当竞争法》的风险**仅在将数据作为产品再发布时**才真实存在。非商业论文、匿名化、不再分发的情形下**实际风险低**，但 robots.txt / ToS 违反是**真实暴露点**。

### 9.7 同类工作与创新点（已核实）——⚠️ 本轮最重要的发现

GitHub 搜索 `影评情感分析` 得 92 个结果，`情感分析 springboot` 得 16 个。**Java 类项目全部是低星毕设工厂仓库**（最高 5 星），形态为 "Spring Boot + MySQL + Python 爬虫 + ECharts"。Python 同类项目星数碾压（最高 227 星）。

**饱和区（不得声称创新）**：SnowNLP/jieba + Flask/Django + ECharts 词云 + 爬豆瓣；LSTM/BiLSTM/TextCNN/Word2Vec 跑 ChnSentiCorp；"情感分析 + 推荐系统"（含 Java 版，数十个）；普通 BERT 微调。

**⭐ 已验证的真实空白：`情感分析 springboot` + `sentiment analysis java spring boot chinese` 搜索返回 0 个通过 ONNX Runtime 部署微调中文 Transformer 的 Java 后端项目。** 所有严肃的模型服务项目都是 Python；Java 项目要么是 CRUD + Python sidecar，要么是传统机器学习。**这是经多种措辞搜索验证的结论，不是假设。**

**创新点强度重排（研究结论）**：
1. **⭐⭐ 纯 Java 通过 ONNX Runtime 部署微调中文 BERT/RoBERTa，推理期零 Python** —— 最强、可验证、有架构意义（单 JVM 部署，无 Python venv/Docker sidecar）。可量化：约 69 MB jar vs 数 GB 的 Python+PyTorch 镜像。
2. **⭐ 方面级（细粒度）情感** —— 确实比文档级罕见，且**不存在中文电影 ABSA 数据集**，自建即为贡献。
3. **⭐ LLM vs 本地蒸馏模型的成本/精度对比** —— 便宜（空闲时段每百万 token ¥1–¥8），且**对比本身即可发表**，产出量化表格。
4. 方面聚合为雷达图/维度画像 —— 单独看很弱（只是一张图），作为 #2 的展示层可以。
5. LLM API + 本地模型兜底 —— 合理工程，但"调了个 API 并缓存"作为创新点太薄。

### 9.8 中文 ABSA 任务与实践风险（已核实）

**任务形式**：ATE（方面词抽取）/ ATSA（方面词+极性）/ **ACSA（方面类别+极性）← 与固定维度（剧情/演技）对应的正是这个** / ASTE（三元组）/ ASQP / ACOS（四元组）。
**中文基准**：ACOS（ACL 2021，[NUSTM/ACOS](https://github.com/NUSTM/ACOS)，餐厅+笔记本，中文）；ASQP（EMNLP 2021，生成式改写范式）；**ASAP**（[Meituan-Dianping/asap](https://github.com/Meituan-Dianping/asap)，360★，美团/大众点评餐厅评论，ACSC + 评分，**最接近中文 ACSC 基准**）。
⚠️ **SOTA F1 数值未能核实**（arXiv 全文检索返回 0，ACL Anthology PDF 被拦，Semantic Scholar 不可达）。**不得把任何 F1 数值写进论文**，须自行从原论文取。
⚠️ **dimABSA（SIGHAN-2024 中文维度 ABSA）的官网 `dimabsa.tech` DNS 已无法解析**，可能已停运。

**简化 ABSA 的真实失败模式（按严重程度排序）**：
1. **隐式方面 —— 致命。** "太拖了"是节奏但没有"节奏"二字；"看睡着了"是节奏；"全程尴尬"是演技/台词。**关键词锚定在构造上就会全部漏掉**，而电影评论中这类可能占多数。
2. **转折句。** "画面很美但是剧情很烂" —— 单一窗口情感会给两个方面同一个极性。**必须在 但是/不过/然而/却 处切分子句再分类。这是性价比最高的一处修复。**
3. 多方面共享一个观点词。4. 否定与反语（"真是太好看了呢"）。5. 领域漂移（通用模型读不懂"烂得很精彩"）。

**有效缓解手段**：转折连词处切句；各方面独立观点词典（拖沓/冗长 → 节奏负面）；要求锚点与观点词**同处一个子句**；**只在锚点显式出现时才报告该方面**（接受低召回、保住高精度，远好过瞎猜）。
**LLM 提示（JSON schema）作对照臂是更好的工程选择**，建议**作为对比臂并行运行**而非二选一。主要失败模式：**幻觉出未提及的方面**（用"仅包含明确提及的方面，否则省略"抑制）、跨次运行标签不一致（温度 0 + few-shot 抑制）。

**学生可辩护的评测方案**：
- **人工标注 300–500 条**（不是 200 条——10 个方面下 200 条每方面仅约 20 个实例，算 per-aspect F1 太薄）。
- **报告 per-aspect 精确率/召回率/F1，不能只报 micro-average**（micro 会掩盖"节奏"很差而"演技"尚可）。
- **双标注 ≥100 条，2 名标注者，报告 Cohen's κ**。惯例：κ>0.8 优秀，0.6–0.8 中等，**<0.6 必须改标注规范，而不是照报数字**。
- **用 LLM 作 silver standard 对照臂**，报告规则系统与 LLM 的一致率；分歧处即误差分析章节。
- **不得声称**：把文档级准确率当作 ABSA 准确率；关键词锚定"达到"了它没有的召回率；未运行的 SOTA 对比；LLM 标注集是 gold。
