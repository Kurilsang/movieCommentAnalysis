## Problem Statement

作为一个要答辩的毕业生，我现在的系统**打不开**。

后端有 44 个 Java 类、101 个测试全绿，AI 算法（L0 规则引擎、方面级分析、关键词提取）在命令行里跑得很好——我用 4000 条真实豆瓣影评验证过。但**打开浏览器，8 个页面全是报错**：

- 首页转圈圈，看不到任何电影
- 点不进详情页，看不到雷达图
- 提交评论按钮点了没反应
- 后台一片空白

原因有两个，都是我实测确认的：

1. **数据库里一张表都没有**。`movie_sentiment` 库是空的，只有测试用的 2 张表（用户、收藏）。没有电影表、没有评论表、没有分析结果表。
2. **前端调的接口，后端根本没写**。前端 8 个页面在调用 `/api/movies`、`/api/comments/analyze` 等 10 个接口，但后端只有 3 个 Controller（认证、收藏、用户管理）——**电影和评论的 Controller 完全不存在**。

这导致我无法演示任何东西。答辩时老师问"打开我看看"，我只能打开命令行。

## Solution

让系统**从命令行走到浏览器**：补上缺失的数据层和接口层，使 8 个前端页面全部能正常打开、显示真实数据、完成核心交互。

做完之后，我能：

1. **打开首页**，看到 20 部真实电影的卡片墙（星际穿越、疯狂动物城……），每张卡片显示好评率，能搜索、能按口碑排序
2. **点进详情页**，看到这部片子的**方面雷达图**（剧情/演技/画面特效/配乐音效 四维）、情感分布饼图、关键词、好评差评代表句（带置信度和触发词）
3. **提交一条自己的评论**，立刻看到情感分析结果和触发词解释——这是答辩现场唯一有交互冲击力的 10 秒
4. **打开后台**，看到爬虫任务列表和数据总览

数据来自已经落盘的 4000 条真实豆瓣影评（apache-2.0 许可），演示全程**不依赖任何实时网络请求**。

## Implementation Decisions

### 数据库设计（新增 5 张表）

现有 2 张表（`sys_user`、`user_favorite`）保持不变，新增：

**`movie`** —— 电影
- `id`（主键，用现有 CSV 的 `M` + md5 前缀作为业务 ID）、`title`、`director`、`actors`、`year`、`poster_url`、`synopsis`
- `comment_count`（冗余计数，避免每次 COUNT）
- `created_at`

**`comment`** —— 评论
- `id`（自增）、`movie_id`（外键）、`text`、`author`、`publish_time`、`like_count`、`rating`（1-5 星真实评分，**必留**，它是唯一的真实标签）
- `created_at`

**`comment_analysis`** —— 文档级分析结果（一条评论一行）
- `id`、`comment_id`、`polarity`（POSITIVE/NEUTRAL/NEGATIVE）、`confidence`、`trigger_words`（JSON 数组）、`analyzer_name`（L0-rule/L2-onnx/L1-llm）、`raw_json`（完整输出快照）、`elapsed_ms`、`created_at`

**`comment_aspect`** —— 方面级结果（**纵表**，一条评论 × 一个维度一行）
- `id`、`comment_id`、`aspect_name`、`mentioned`、`polarity`、`confidence`、`sample_count`、`trigger_words`（JSON）、`created_at`
- **为什么用纵表**：维度集合可能调整（覆盖率统计已发现"节奏""台词"低于 5% 阈值需替换），纵表零迁移成本

**`crawler_task`** —— 爬虫任务
- `id`、`movie_id`、`status`（PENDING/RUNNING/SUCCESS/FAILED）、`progress`（0-100）、`message`、`started_at`、`finished_at`

### 建表与初始化方式

- 用 **Spring Boot `schema.sql`** 自动建表（`spring.sql.init.mode=always`），部署时零手工操作
- 用**一次性数据导入程序**把 `data/movies.csv` + `data/comments.csv` 灌进数据库（幂等：重复执行不产生重复数据）
- 导入后**预计算**每部电影的分析结果并落库，使详情页接口是纯查询（不实时算 200 条评论）

### 接口契约（必须与前端实际调用严格对齐）

前端 `api.js` 已固定调用以下路径，后端按此实现，**不改前端**：

**电影**
- `GET /api/movies?sort=&q=` → `{ movies: [{ id, title, year, director, posterUrl, positiveRate, commentCount }] }`
- `GET /api/movies/{id}` → `{ movie: { id, title, director, actors, year, posterUrl, synopsis, sentimentDistribution: { positive, neutral, negative } } }`
- `GET /api/movies/{id}/analyze` → `{ aspects: {...}, positiveComments: [...], negativeComments: [...] }`
- `GET /api/movies/{id}/keywords` → `{ keywords: [{ word, weight, count }] }`

**评论**
- `POST /api/comments/analyze`（body: `{ text, model }`）→ `{ result: {...}, taskId }`
- `GET /api/comments/result/{taskId}` → `{ result: {...} }`

**后台**
- `GET /api/admin/crawler/tasks` → `{ tasks: [...] }`
- `POST /api/admin/crawler/trigger`（body: `{ movieId, maxCount }`）→ `{ taskId }`
- `POST /api/admin/analysis/rerun-all` → `{ message, count }`

### ⚠️ 已发现的字段名不一致（必须修）

前端雷达图读的是 `aspects[n].sampleCount` 和 `aspects[n].smoothedScore`，但后端 `AspectAggregate` 的字段名是 **`mentionedCount`**（不是 `sampleCount`），`smoothedScore` 是对的。

**决策**：在 API 响应层统一映射为前端期望的名字（`sampleCount`），而不是改前端——因为 `AspectResult` 已经用了 `sampleCount`，统一到 `sampleCount` 更一致。

### 分析结果的数据流

- **详情页**（`/api/movies/{id}/analyze`）：读**预计算**的落库结果，聚合到电影级。不实时计算。
- **提交评论**（`/api/comments/analyze`）：**实时**调用 `SentimentAnalyzer`，返回结果，同时落库。
- **一键重跑**（`/api/admin/analysis/rerun-all`）：遍历所有评论，重新分析并覆盖落库结果。

### 维度调整（覆盖率统计的结论）

覆盖率实测（4000 条）：剧情 12.95%、演技 7.98%、画面特效 5.23%、配乐音效 5.43%、**节奏 2.20%**、**台词 1.33%**。

**决策**：P0 阶段雷达图**只展示四个达标维度**（剧情、演技、画面特效、配乐音效）。"节奏""台词"的替换留到 P1（需要重新设计词典并验证覆盖率），P0 不阻塞。

### 复用既有代码（不重写）

- `SentimentAnalyzer` 接口 + `L0RuleSentimentAnalyzer`（测试接缝，已有 15 个测试）
- `RuleBasedAspectAnalyzer`（方面级，已有 10 个测试）
- `TfIdfKeywordExtractor`（关键词，已有 5 个测试）
- `JwtUtil` / `SecurityConfig` / `UserService`（认证，已有 7 个测试）
- `CommentCsvExporter` / `MockReviewCrawler`（爬虫，已有 13 个测试）
- **P0 只做"接线"，不改这些已验证的算法**

## Testing Decisions

### 什么是好测试

只测**外部行为**，不测实现细节。给一个 HTTP 请求，断言响应 JSON 的字段和值；给一条 SQL 查询，断言数据落库正确。**不测** Service 内部调用了哪个 Mapper、不测 SQL 语句文本、不测 Vue 组件渲染。

### 测试接缝（P0 新增一个，全系统共两个）

| 接缝 | 用途 | 状态 |
|---|---|---|
| `SentimentAnalyzer.analyze(text)` | AI 算法行为（已有 15 个测试） | 保留 |
| **HTTP API 边界（MockMvc）** | P0 的接口契约 + 数据落库 | **新增** |

**为什么是 HTTP 边界**：P0 交付的是"页面能打开"，页面能不能打开完全由 HTTP 响应决定。测 HTTP 边界 = 测用户能看到什么，这是最高接缝。

**测试用 H2 内存库**（已有 `application-test.yml` 配置），不依赖本地 MySQL 状态。

### 要测的模块

1. **建表脚本**：Spring 上下文启动后，5 张新表存在
2. **数据导入**：导入 4000 条后，`comment` 表行数正确；重复导入不产生重复
3. **电影列表接口**：返回 20 部电影；按好评率排序时顺序正确；搜索能过滤
4. **电影详情接口**：返回电影元数据 + 情感分布（正+中+负 = 评论总数）
5. **雷达图接口**：返回四个维度的 `smoothedScore` 和 `sampleCount`（**字段名必须是 `sampleCount`**）；样本量 < 10 的维度 `sufficientData=false`
6. **关键词接口**：返回非空列表，按权重降序
7. **提交评论接口**：返回极性 + 置信度 + 触发词；未登录时返回 401；空文本返回 400
8. **爬虫任务接口**：触发后任务落库；任务列表能查到
9. **一键重跑接口**：重跑后分析结果行数不变（覆盖而非新增）
10. **权限**：普通用户访问 `/api/admin/**` 返回 403

### 测试的先例

- `UserServiceTest`（`@SpringBootTest` + H2 + `schema-test.sql`）—— P0 的接口测试沿用同样的配置方式
- `L0RuleSentimentAnalyzerTest`（纯单元测试，无 Spring）—— 算法层测试的先例

## Out of Scope

- **不做** L2 ONNX 模型导出（P1；当前 `ml/models` 不存在，L2 跑不了）
- **不做** L1 大模型真实调用（P1；需要 API Key）
- **不做** 扩充 L0 词典到 300-500 词（P1；当前 60 词导致 Accuracy 仅 37.4%）
- **不做** HanLP 分词接入（P1；当前关键词有 `12`、`the` 等噪声）
- **不做** "节奏""台词"维度的替换（P1；需要重新验证覆盖率）
- **不做** 自建标注集（P2）
- **不做** θ 敏感性分析实验（P2）
- **不做** 模型管理页面（P2）
- **不做** Docker 部署（公司电脑无虚拟化权限，本地免安装 MySQL 已可用）
- **不做** 评论时间趋势图（数据集无时间字段，`publishTime` 为空）
- **不改前端代码**（前端 8 个页面已写好，P0 只补后端）
- **不重写**任何已验证的算法类

## Further Notes

1. **数据集无时间字段**：`data/comments.csv` 的 `publishTime` 列是空的（源数据集没有日期）。所以详情页的"评论时间趋势图"**做不了**，前端已实现该图但在无数据时应隐藏。

2. **数据集无电影元数据**：`data/movies.csv` 的 `director`/`actors`/`year`/`posterUrl`/`synopsis` 全为空（源数据集没有）。前端已做占位处理（"未知导演"、"暂无海报"）。P0 接受空值，不阻塞。

3. **星级分布不平衡**（实测）：正面 84.4% / 中性 13.6% / 负面 2.0%。这意味着"全猜正面"就有 84.4% 准确率。**论文评测必须用 macro-F1**，P0 不涉及。

4. **L0 基线实测 Accuracy 仅 37.4%**（比全猜正面差一半）。P0 不修，但要知道：详情页显示的雷达图分数是基于这个弱基线算出来的，P1 扩词典后会显著改善。

5. **答辩演示脚本**（P0 完成后可演示的）：
   - 首页海报墙 + 排序（30 秒）
   - 详情页雷达图 + 饼图 + 代表句（2 分钟，主战场）
   - 现场提交评论 → 实时分析 + 触发词解释（2 分钟，唯一交互冲击）
   - 后台爬虫日志 + 数据总览（1 分钟）

6. **验收方式**：P0 完成的唯一标志是——打开 `http://localhost:5173`，**8 个页面全部无报错**，首页有 20 部电影，详情页有雷达图。
